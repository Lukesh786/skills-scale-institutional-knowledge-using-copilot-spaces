# OctoAcme Project Management Docs

OctoAcme’s project management approach centralizes process knowledge, accelerates onboarding, and enables consistent and repeatable project execution. The docs in this folder provide actionable guidance, workflows, and templates for every phase—from initiation to retrospective.

## Overview of OctoAcme Project Management Processes

- **Purpose:** Enable cross-functional teams to deliver customer value efficiently and transparently. Provide equal, versioned access to institutional knowledge, reduce dependency risk, and support rapid onboarding.
- **Principles:** Customer-first, iterative delivery, clear ownership, data-informed decisions, psychological safety.
- **Lifecycle:** Initiation → Planning → Execution & Tracking → Release → Close & Retrospective.
- **Core Roles:** Project Manager (PM), Product Manager (PdM), Developers, QA, Stakeholders. See [Roles and Personas](./octoacme-roles-and-personas.md).
- **Artifacts:** Project Charter, Roadmap, Backlog, Risk Register, Release Notes, Retrospectives.
- **Team Practices:** Project boards, pull request conventions, CI automation, risk management, regular demos, and continuous improvement.

These processes ensure that every team member has equal access to workflows, decision rationales, and ongoing improvements. OctoAcme encourages feeding validated improvements back into living documentation for collective benefit. For contributing or updating process docs, use the issue template in `.github/ISSUE_TEMPLATE/`.
